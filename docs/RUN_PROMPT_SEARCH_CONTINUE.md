# v2 5라운드 결과에서 6~10라운드로 연장

## 10라운드까지 연속 실행

사용자 요청에 따라 남은 라운드를 일괄 승인하는 옵션을 추가했다. 준비된 계획에서:

```powershell
python -m residue_experiment.prompt_search_continue run --mode live --through-round 10 --max-calls 3960
```

이 명령은 최대 10라운드까지 추가 승인 없이 진행한다. 6라운드 시작 시 미개선 횟수를
0으로 초기화하고, 이후 2라운드 연속 개선이 없으면 조기 종료한다. 5라운드의 미개선은 이어받지 않는다. 예산 도달·오류 시 중단하고, 동일 명령으로 재실행하면 미완료 라운드부터
진행한다. 완료된 라운드는 재실행하지 않으며 진행 중 라운드의 성공 호출도 재사용한다.
`--max-calls`는 여전히 모든 추가 라운드를 합친 누적 상한이다. `approval-through-10.json`에
일괄 승인 범위를 기록한다. 아래의 라운드별 승인 방식도 선택적으로 사용할 수 있다.

기존 v2의 R4C2, 선택 성능, 누적 사례 50개와 성공한 개발·선택 예측을 이어받는다.
기존 결과를 수정하지 않고 `results/prompt-search-v2-continued-patience2`에 별도 저장한다.
2023~2025년 평가 문제나 결과는 후보 생성·채택에 사용하지 않는다.

## 자료 순회

| 라운드 | 자료 |
|---|---|
| 1~5 | 기존 완료 결과 유지: 개발 250개 |
| 6 | 기존 개발 순서의 다음 50개: 첫 순회 300개 완료 |
| 7 | 첫 순회에서 제외된 26개를 우선 포함하여 두 번째 순회 시작 |
| 8~10 | 두 번째 순회의 다음 50개씩 사용 |

첫 순회의 마지막 26개만으로 작은 라운드를 만들지 않는다. 두 번째 순회는 326개를
고정 시드로 재배열하되 제외됐던 26개를 맨 앞에 배치한다. 같은 순회 안에서는 중복이 없다.
10라운드는 두 번째 순회의 네 번째 배치까지이며 두 번째 순회 전체 완료는 아니다.

현재 지침의 응답과 정답을 비교하여 오류를 갱신한다. 같은 지침·모델·입력·호출 설정이면
성공 응답을 재사용하므로 매번 새로운 확률적 응답을 샘플링하는 실험은 아니다.
누적 사례는 최대 10개를 선택한 후 기존 ID와 합쳐 중복을 제거한다. 따라서 재등장한 사례가
있으면 실제 추가 수가 10개보다 작아질 수 있다. 이미 누적된 사례라도 이번 배치에서 틀렸으면
교정 대상에 포함될 수 있다. 채택 조건은 v2와 같다.

## 실행

프로젝트 루트에서 최초 준비(오프라인):

```powershell
python -m residue_experiment.prompt_search_continue prepare
```

6라운드만 승인하고 실행:

```powershell
python -m residue_experiment.prompt_search_continue run --mode live --round 6 --approve-round --max-calls 3960
```

완료 결과를 검토한 뒤 다음 라운드를 각각 승인한다. 전체 실행 루프를 사용하지 않는다.

```powershell
python -m residue_experiment.prompt_search_continue run --mode live --round 7 --approve-round --max-calls 3960
```

같은 방식으로 `--round 8`, `--round 9`, `--round 10`을 하나씩 실행한다.
실행 도중 예산에 걸려 멈췄으면 같은 라운드로 재개한다. 이미 완료한 라운드를 다시 실행하거나
다음 라운드를 건너뛰면 거부한다. `--approve-round`가 없으면 호출하지 않는다.
각 승인 내역은 `approval-round-NN.json`에 저장한다.

상태 확인:

```powershell
python -m residue_experiment.prompt_search_continue status --mode live
```

6라운드부터 새로 센 미개선 횟수가 연속 2회이면 `final_prompt.json`을 저장하고 종료한다.
개선 시 횟수는 0으로 초기화한다. 종료 후 동일 명령을 실행해도 더 진행하지 않는다.
6·7라운드가 모두 미개선이면 7라운드에서 종료하며 최대 10라운드까지만 진행한다.

## 비용과 캐시

`--max-calls`는 **연장 폴더에서 발생한 추가 요청의 누적 상한**이다.
기존 3,370회나 별도 연도 평가 840회를 합산하지 않는다.
3,960회는 캐시 절감을 보수적으로 제외한 6~10라운드 탐색의 상한이며 실제 호출은 더 적을 수 있다.
각 라운드 예산 상한은 개발 50 + 현재 지침 누적 최대 N + 분석·생성 2 + 선택 420 + 후보 누적 3N이다.
N=60,70,80,90,100으로 합산했다. 최종 연도별 평가는 포함하지 않는다.
원한다면 더 낮은 누적 상한을 지정할 수 있으며 예산 도달 시 다음 호출 전에 정지한다.

원본 개발·선택 성공 응답은 요청과 함께 `seed_cache.json`으로 복사하고 해시를 검증한다.
정확히 같은 요청의 예측만 재사용한다. 이전 분석·생성·최종 평가 호출은 가져오지 않는다.
새 응답은 `live/calls/`에 기록한다. 실패·중단 상태는 자동 재시도하지 않는다.
모델과 호출 설정은 원래 v2에서 상속하고 변경하지 않는다.

`--mode mock`은 별도 폴더에서 합성 응답으로 실행하며 원본 live 예측을 캐시로 사용하지 않는다.
출발 지침과 누적 ID는 동일하지만 mock 성능은 연구 결과가 아니다.

## 결과

빈 응답으로 `invalid_response: expected exactly Yes or No`가 발생하면, 실행이 종료된 뒤 아래 복구 명령을 사용한다. 유료 호출 없이 성공 상태의 빈 예측만 `empty_response_attempts/`로 보관한다. 정상 응답과 미완료 호출은 건드리지 않으며, 보관한 호출도 누적 예산에 포함한다.

```powershell
python -m residue_experiment.prompt_search_continue repair-empty --mode live
python -m residue_experiment.prompt_search_continue run --mode live --through-round 10 --max-calls 3960
```

두 번째 명령은 유료 실행을 재개한다. 빈 응답의 재발 원인을 제거하는 기능은 아니며, 또 발생하면 안전하게 중단한다. 실행 잠금이 남아 있으면 먼저 기존 실행 종료 여부를 확인한다.

`live/round-06` ~ `round-10`에 개발 예측, 누적 사례·예측, 후보 지침,
선택 예측, 교정·악화 및 채택 결과를 저장한다. 조기 종료 또는 10라운드 완료 시 `live/final_prompt.json` 생성.
원본 1~5라운드 파일은 원래 v2 폴더에서 확인하고, 연장 plan에는 원본 계획 해시와 출발 상태를 기록한다.
이번 명령은 후보 탐색만 수행하며, 2023년 또는 연도 확장 평가를 자동 실행하지 않는다.
