# R6C1 후속 실험: 위험평가용 35개 + 단속용 15개

기존 고정 10개 실험을 변경하지 않고 `results/r6c1-risk-search-mixed`에 새 계획을 준비했다. 시작 지침은 R6C1, 최대 5라운드, 연속 미개선 2회 종료다.

```powershell
python -m residue_experiment.risk_search run --mode live --max-calls 3650
```

첫 라운드만 실행:

```powershell
python -m residue_experiment.risk_search run --mode live --through-round 1 --max-calls 762
```

이후 전체 실행 명령으로 이어서 진행한다. 호출 한도는 이 폴더의 누적 상한이다. 준비를 다시 해야 할 때는 `python -m residue_experiment.risk_search prepare`를 실행한다. 기존 계획이 있으면 일치하는지 확인하며, 임의로 덮어쓰지 않는다.

## 매 라운드

1. 개발 326개에서 미리 고정한 순서로 위험평가용 35개·단속용 15개를 선택한다. 첫 라운드의 위험평가용 35개에는 사전 선정한 10개가 포함된다. 유형별 전체 자료를 다 사용한 뒤 재순회한다. 한 라운드 안에는 같은 ID가 중복되지 않는다.
2. 현재 지침으로 새 50개 및 이전 라운드에서 선정한 중요 사례를 평가한다. 모델·입력·설정·지침이 같은 기존 유효 응답은 재사용한다.
3. 첫 라운드는 사전 선정한 10개를 수정용 입력으로 사용한다. 이후에는 이번 50개의 현재 오답 중 위험평가용 우선 최대 6개를 고르고, 정답 사례를 추가해 최대 10개를 구성한다. 정답은 오류 입력과의 단어 집합 유사도를 기준으로 정렬하고 단속용·No·Yes 보호 사례를 가능한 범위에서 포함한다. 이는 자동 휴리스틱이지 전문가가 검증한 의미적 반례 선정이 아니다. 실제 오류 유형은 수정용 LLM에 근거와 한계를 분석하도록 요청한다.
4. 입력 누락·정답 근거 재확인이 필요하다고 분석한 7개 ID는 자동 수정용 선정에서 제외한다. 검증에서는 제외하지 않는다. 해당 목록은 계획의 `optimizer_excluded_ids`에 명시한다.
5. 선정된 사례를 중복 없이 메모리에 저장한다. 후보 3개를 생성하고 현재 50개와 과거 메모리에서 위험평가용·단속용의 교정/악화를 각각 확인한다. 수정용 LLM에는 이번에 선정한 최대 10개만 전달하며, 과거 메모리 전체나 선택 자료 정답은 전달하지 않는다.
6. 목표 오류 하나 이상 교정하고, 개발 재검증에서 두 유형 각각 정답 수가 줄지 않아야 한다. 선택 자료 140개에서는 현재 지침 대비 위험평가용 정확도 상승, 단속용 정확도 비감소를 모두 만족해야 채택한다. 전체 정확도, Macro-F1, 짧은 지침, 생성 순으로 동점을 처리한다.
7. 현재 배치에 선정 가능한 오류가 없으면 후보 생성을 생략하고 미개선 1회로 계산한다. 첫 10개가 해결됐다는 이유만으로 즉시 종료하지 않는다. 연속 2회 미개선 또는 최대 5라운드에서 종료한다.

## 비용과 기록

연결 오류로 실행이 종료된 경우, 로그에서 지목된 호출 ID만 별도 보관한 후 재개할 수 있다. 복구 명령은 API를 호출하지 않으며 실패 기록을 `live/connection_error_attempts/`에 보존한다. 실패한 시도도 누적 호출 한도에 포함한다. `started` 등 처리 여부가 불명확한 다른 상태나 정상 응답은 이 명령으로 이동하지 않는다.

```powershell
python -m residue_experiment.risk_search repair-connection --mode live --call-id 6660f5fa70ecbb7f7be4d063183ed049703afb534469857cccf991cb1b9f1db8
python -m residue_experiment.risk_search run --mode live --max-calls 3650
```

복구는 기존 실행이 종료되고 잠금이 해제된 상태에서만 수행한다. 연결 실패는 서버 처리·과금 여부가 불확실할 수 있으므로 재시도 시 추가 비용이 생길 수 있다. 정상 응답·생성 후보는 재사용한다.

검증 자료는 새 50개 + 과거 중요 사례(최대 라운드당 10개 추가)다. 따라서 후보 검증이 항상 정확히 50개인 것은 아니며, 5라운드에는 최대 90개다.
캐시를 제외한 보수적 상한: 초기 선택 평가 140회 + 각 라운드 현재 검증 + 분석/생성 2회 + 후보 3개의 개발/선택 평가 = 최대 3,650회. 1라운드까지는 최대 762회. 기존 캐시·조기 종료로 실제 호출은 줄어든다.

각 라운드의 `memory.json`에 배치·수정용 선정·누적 ID를 저장한다. `optimizer_input.json`에 실제 수정 요청, `selection.json`에 후보별 유형 성능·채택 이유를 저장한다. 종료 시 `live/final_prompt.json`을 저장한다. 데이터 전체 재평가 및 2023~2025년 최종 평가는 자동 실행하지 않는다.

이 실험은 이미 반복 사용한 선택 자료를 사용한다. 선택 성능 상승을 독립적인 일반화 검증으로 해석하지 않는다. 새 보호 조건은 정확도 비감소이며, 기존 정답이 한 건도 악화되지 않는다는 의미는 아니다.
